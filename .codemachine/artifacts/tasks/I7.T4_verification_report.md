## Error Handling

**HTTP Status Codes:**
- **200 OK**: Successfully authenticated, tokens returned
- **400 Bad Request**: Invalid parameters (missing code, protocol, email, redirectUri, codeVerifier)
- **401 Unauthorized**: SSO authentication failed, domain mismatch, organization not found, SSO not configured
- **500 Internal Server Error**: Unexpected exceptions

**Error Response Format:**
```java
{
  "code": "DOMAIN_MISMATCH",
  "message": "Email domain does not match organization domain"
}
```

## Key Design Patterns

### 1. Fire-and-Forget Audit Logging
Audit logging called after token generation (line 529), but response not delayed waiting for audit log persistence. This is the correct pattern for non-blocking audit logging.

### 2. Graceful Duplicate Member Handling
`OrganizationService.addMember` throws `IllegalStateException` if user already member. `AuthController` recovers from this exception (lines 510-516) and continues to token generation. This enables seamless SSO login for returning users without failing the request.

### 3. Reactive Error Recovery Pattern
Uses `.onFailure(IllegalStateException.class).recoverWithItem()` to handle expected duplicate member scenario. Returns null to continue reactive chain instead of propagating exception.

### 4. Protocol-Specific Parameter Handling
OIDC requires redirectUri and codeVerifier (lines 417-425), SAML2 doesn't (lines 463-465). `SsoAuthParams` constructed conditionally based on protocol.

## SSO Authentication Flow Sequence

1. **Request Validation** (lines 397-432)
   - Validate code, protocol, email parameters
   - For OIDC: validate redirectUri and codeVerifier
   - Extract IP address and User-Agent from HTTP headers

2. **Organization Lookup** (lines 436-443)
   - Extract email domain from user email
   - Look up organization by email domain
   - Fail if no organization found for domain

3. **SSO Configuration Validation** (lines 449-453)
   - Verify organization has SSO configured
   - Fail if organization.ssoConfig is null/empty

4. **SSO Authentication** (lines 456-473)
   - Build SsoAuthParams (codeVerifier/redirectUri for OIDC)
   - Call SsoAdapter.authenticate with org's SSO config
   - Receive SsoUserInfo with user profile

5. **Domain Verification** (lines 479-485)
   - Extract user's email domain from SsoUserInfo
   - Verify user domain matches organization domain
   - Fail if domains don't match (security check)

6. **JIT User Provisioning** (lines 489-495)
   - Call UserService.findOrCreateUser
   - Create user if doesn't exist
   - Return existing user if found

7. **Organization Assignment** (lines 502-516)
   - Call OrganizationService.addMember with MEMBER role
   - Handle IllegalStateException if user already member
   - Continue to token generation even if member exists

8. **JWT Token Generation** (lines 522-526)
   - Call JwtTokenService.generateTokens
   - Build TokenResponse with access token, refresh token, expiry, user DTO

9. **Audit Logging** (lines 529-534)
   - Call AuditLogService.logSsoLogin
   - Fire-and-forget async audit event

10. **Response** (line 539)
    - Return 200 OK with TokenResponse
