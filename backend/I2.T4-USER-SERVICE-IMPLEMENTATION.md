## Architecture & Design Patterns

### 1. **Reactive Programming**
- Mutiny `Uni` types for non-blocking I/O
- Pipelines with `flatMap`, `onItem`, `switchTo`
- Reactive failure propagation via `Uni.createFrom().failure()`

### 2. **Transaction Management**
- `@WithTransaction` for write operations (create, update, delete)
- `@WithSession` for read operations (get, find)
- Automatic transaction boundaries via Quarkus annotations

### 3. **Dependency Injection**
- CDI `@ApplicationScoped` service bean
- `@Inject` for repository and ObjectMapper dependencies
- Constructor injection via Mockito for testing

### 4. **Repository Pattern**
- Service delegates persistence to Panache repositories
- Custom finder methods: `findActiveByEmail()`, `findByOAuthProviderAndSubject()`
- Soft-delete filtering at repository layer

### 5. **Domain-Driven Design**
- Service encapsulates business logic
- Entities (User, UserPreference) as POJOs with public fields
- Value objects (UserPreferenceConfig) as immutable DTOs

### 6. **Validation Strategy**
- Early validation in reactive pipeline
- Fail-fast with descriptive exceptions
- Regex patterns and length constraints
- Bean Validation annotations on entities

### 7. **Error Handling**
- Custom exceptions: `UserNotFoundException`
- Reactive failure propagation
- Serialization errors wrapped in `IllegalArgumentException`
- Null-safe operations with explicit null checks

### 8. **JSON Serialization**
- Jackson ObjectMapper for JSONB fields
- Type-safe config objects (UserPreferenceConfig)
- Fallback to empty JSON on serialization failure
- `@JsonInclude(NON_NULL)` for compact JSON
